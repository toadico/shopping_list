# Shared Shopping List (Self-Hosted PWA)

An open-source, self-hosted collaborative shopping list built with **Node.js (LTS, ESM, TypeScript strict)**, **Next.js (React)**, **Express**, and **SQLite (`better-sqlite3`)**.

## Key Features
1. **Rich Item Creation**:
   - Select from a shared list of stores **or** add a new store inline simply by typing its name.
   - Take a picture with your device camera (live WebRTC viewfinder or native mobile camera capture) and attach it directly to the shopping list item.
2. **Progressive Web App (PWA) & Offline-First**:
   - Web App Manifest (`public/manifest.json`) & Service Worker (`public/sw.js`).
   - Full **IndexedDB offline cache storage** for all shopping list items and stores.
   - **Background Sync** (`sync-shopping-items`) and automatic online queue replay so items added, checked off, or deleted offline sync seamlessly when connectivity returns.
3. **Zero-Config Console Admin + QR Code Onboarding Security**:
   - Only authenticated users of the system can access the shopping list.
   - The initial user `shopping_admin` is the only user with a username and password.
   - On the first start of the container, a cryptographically random password is generated for `shopping_admin` and stored in SQLite.
   - Each time the Docker container starts, the `shopping_admin` password is displayed **only on the container console (`stdout`)**.
   - Additional users are invited by scanning a **QR Code** generated by either `shopping_admin` or any active user who currently has access.
   - New users enter their **Name** and receive a random **API key** (`slk_...`) that expires after 90 days of inactivity and automatically renews for 90 days on every access.
   - `shopping_admin` can view all users of the system and **disable**, **re-enable**, or **revoke** their access at any time.
4. **Production Resilience & Security**:
   - Graceful shutdown handlers (`SIGTERM`, `SIGINT`) that drain active HTTP connections and cleanly close SQLite.
   - Kubernetes/Docker `/healthz` (liveness) and `/ready` (readiness) probes.
   - Security headers via **Helmet**, **CORS**, **express-rate-limit**, and recursive input sanitization + **Zod** validation.

## Quick Start with Docker Compose

`PUBLIC_BASE_URL` is required to start the container:

```bash
PUBLIC_BASE_URL=http://localhost:3000 docker compose up --build -d
```

View the container console logs to get the `shopping_admin` password:

```bash
docker compose logs shopping-list
```

You will see a banner printed to the container console:
```text
====================================================================
  SHARED SHOPPING LIST — CONTAINER CONSOLE ADMIN CREDENTIALS
====================================================================
  Initial Admin Username : shopping_admin
  Initial Admin Password : <randomly-generated-password>
====================================================================
```

Open `http://localhost:3000` and sign in as `shopping_admin`.
